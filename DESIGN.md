# Application Design & Architecture (DESIGN.md)

This document outlines the UI/UX design philosophy, module structures, and database architectures for the Control Disbursement (CCD) Application.

## 1. UI/UX Philosophy

The application employs a **Modern, Premium, Data-Heavy Dashboard Design**:
- **Layout:** A persistent collapsible sidebar on the left and a top header containing user profiles/logout actions. The main workspace sits centrally.
- **Color Palette:** Professional deep blues, grays, and crisp whites. Hover effects, subtle shadows, and glassmorphism hints are used to create depth.
- **Components:** Information is sectioned into structured cards (`.icl-card`). Buttons and inputs use soft rounded corners (`border-radius: 8px`).
- **Typography:** Sans-serif (e.g., Inter, Roboto), maintaining high contrast and clear hierarchy.

### CSS Design Tokens
When creating new pages, strictly utilize existing global utility classes (likely defined in `styles.css` or inherited from existing pages):
- `.icl-page`: Wraps the entire view.
- `.icl-page-header`, `.icl-page-title`: Standardized page headers.
- `.icl-card`, `.icl-card-header`, `.icl-card-title`: Wrappers for distinct functional sections (forms, summaries, tables).
- `.icl-table`: The standard data table class. Always wrap tables in a responsive `.table-wrapper`.
- **Action Elements:** `.btn-primary-icl`, `.btn-ghost`, `.btn-clear-filter`.
- **Form Elements:** `.filter-input`, `.form-group`, `.drop-zone`.

## 2. Core Modules

### 1. Dashboard (`/dashboard`)
- Landing page after authentication.
- Displays high-level analytics, recent activity, and quick-access cards to other modules.

### 2. Administration (`/administration`)
- **Purpose:** User Access & Role Management.
- **Roles:** Administrator (Full control), Standard User (Operational tasks), Guest (Read-only).
- **Features:** Table of existing users, modal for creating/editing users, capability to revoke access.

### 3. Issuance Management (`/issuance-management`)
- **Purpose:** Tracking issued checks.
- **Features:** Table view of issuances, Add Issuance form (Account, Serial, Date, Amount, Beneficiary Name, Beneficiary Address), and CSV bulk import functionalities.
- **Database:** `issuance.db` -> `issuance_records`.

### 4. Stop Payments (`/stop-payments`)
- **Purpose:** Managing check stop instructions.
- **Features:** UI to manually add stops, upload bulk CSV stops, or add a range of serial numbers. It prevents cashing of flagged checks.
- **Database:** `stop_payments.db` -> `stop_payment_records`.

### 5. ICL Parser (`/icl-parser`)
- **Purpose:** Ingests and visually renders X9.37 / X9.100 Image Cash Letter files.
- **Features:** Drag-and-drop file upload, parsing of Record Type 25 (Standard) and 31 (Returns), automated TIFF-to-PNG image conversion, Check Data table visualization, and an interactive Image Lightbox for inspecting check fronts/backs.
- **Database:** `issuance.db` -> `icl_files` (Historical uploads tracking).

### 6. Check Processing (`/check-processing`)
- **Purpose:** Evaluates parsed ICL check data against the Issuance and Stop Payments databases to flag exceptions (e.g., matching serial numbers to stop lists or validating amounts).

## 3. Database Schemas (SQLite)

### Admin Database (`admin.db`)
* **users:** `id`, `username`, `password`, `role`, `firstName`, `lastName`, `email`, `phone`, `status`.

### Issuance Database (`issuance.db`)
* **issuance_records:** `id`, `accountNumber`, `serialNumber`, `issueDate`, `amount`, `beneficiaryName`, `beneficiaryAddress`, `status`.
* **icl_files:** `id`, `fileName`, `uploadDate`, `fileType`, `totalCount`, `totalAmount`.

### Stop Payments Database (`stop_payments.db`)
* **stop_payment_records:** `id`, `accountNumber`, `serialNumber`, `amount`, `payeeName`, `stopDate`, `reason`, `status`.

## 4. State Management & Data Flow
- **Frontend State:** Managed via Angular Component properties and RxJS Subscriptions.
- **APIs:** RESTful endpoints built with Express.js. Data is transported via JSON.
- **Images:** X9 check images are parsed in the backend, saved to `server/uploads/icl`, and statically served back to the Angular UI via URLs generated by the API.
